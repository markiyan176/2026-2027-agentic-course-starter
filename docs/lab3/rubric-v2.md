# Рубрика судді — версія v2 (після однієї ітерації калібрування)

Кожен вимір оцінюється окремим ізольованим запитом до моделі `ollama/qwen3:4b@2026-11`.
Додано конкретні приклади на кожен із трьох станів (`pass`, `fail`, `unknown`) за висновками Huynh та ін. (arXiv:2605.06283) без додавання підкритеріїв.

| Вимір | `pass` (з прикладом) | `fail` (з прикладом) | `unknown` (з прикладом) |
|---|---|---|---|
| `acceptance_met` | Кожна команда з `acceptance` у `run.json` завершилася з `exit: 0`. Приклад: у `t-01-1794764400000/run.json` обидві команди `npm run typecheck` і `vitest` мають код `0`. | Хоч одна команда `acceptance` завершилася з `exit !== 0` або критерій явно порушено в `stopped-verify.json`. Приклад: `SUBMIT.total = 10` замість `20` у `c-03`. | Прогін перервано за лімітом кроків (`budget_or_turns`) або таймаутом до запуску команд `acceptance`. Приклад: у `t-08-stopped-1794765000000` спрацював `isStepCount(3)` до етапу перевірки. |
| `scope_respected` | Усі рядки `+++ b/<файл>` у непорожньому `patch.diff` належать до `task.files`. Приклад: `+++ b/scripts/validate-golden.ts` при `files: ["scripts/validate-golden.ts"]` у `c-07`. | У `patch.diff` є файл поза `task.files`. Приклад: зміна `tests/verify.test.ts` при `files: ["src/verify/schema.ts"]` у `c-08`. | Файл `patch.diff` порожній через передчасне зупинення циклу (`budget_or_turns`) на задачі, де очікувалися зміни, тому список торкнутих файлів ще не сформований (приклад: `c-09`). |
| `reason_stated` | Повідомлення у `output.txt` називає *причину* зміни («тому що», «щоб заблокувати», «гарантує»). Приклад: пояснення fail-closed блокування `unknown` у `c-11`. | Повідомлення лише перелічує змінені файли без пояснення причини. Приклад: `"Updated scripts/verify.ts."` у `c-12` — це `fail`, навіть якщо файл правильний. | В артефакті немає тексту пояснення коміту (наприклад, збережено лише службовий лог зупинення `isStepCount` у `c-13` або таблицю JSON-вердиктів у `c-20`). |
