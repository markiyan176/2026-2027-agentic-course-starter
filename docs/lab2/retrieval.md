# Гібридний пошук і цитування

## 1. З чого складається
- **Індекс**: [`data/index.json`](../../data/index.json), ембедер `ollama:embeddinggemma-2:270m` (`768` вимірів), `37` фрагментів по `12` документах (крок 04).
- **Гілка змісту**: `cosineSimilarity` з пакета `ai` між вектором запиту та векторами фрагментів (`src/rag/search.ts`), відбирається топ-`20` (`DEPTH = 20`).
- **Гілка слів**: власна чиста реалізація Okapi BM25 у [`src/rag/bm25.ts`](../../src/rag/bm25.ts) з гіперпараметрами `k1 = 1.2, b = 0.75` (як у SQLite FTS5), відбирається топ-`20` (`DEPTH = 20`); токенізація кирилиці й латиниці регулярним виразом `/[\p{L}\p{N}]+/gu` у нижньому регістрі з відсіканням токенів довжиною `≤ 1`; стемінгу та списку стоп-слів немає.
- **Злиття**: Reciprocal Rank Fusion у [`src/rag/rrf.ts`](../../src/rag/rrf.ts), формула `score(d) = Σ 1 / (60 + rank_i(d))` (`RRF_K = 60`), ранги рахуються з `1`, відсутній у списку документ додає `0`, при рівності балів — детерміноване сортування за `id.localeCompare`.
- **На вихід**: топ-`5` фрагментів (`topK = 5`).
- **Вектор запиту**: той самий ембедер `ollama:embeddinggemma-2:270m` (`768` вимірів, без спеціальних префіксів; для резервного Шляху Б `gemini-embedding-2` передається `taskType: 'RETRIEVAL_QUERY'`).

## 2. Формат цитати
Рядок цитати, який формує функція `renderCitation(toCitation(chunk, quote))` у [`src/rag/cite.ts`](../../src/rag/cite.ts):
`[doc-05#0002] doc-05 › doc-05: Гібридний пошук BM25 + Вектори, злиття RRF та коди помилок індексу › 3. Спеціальні коди діагностики пошукового ядра (E-418 та E-503-RAG) · символи 1814–2649`

- **Зсуви `start` і `end`**: `0-based` (рахуються з нуля, права межа виключна: `slice(start, end)`), вимірюються у **нормалізованому** тексті документа (`normalize(raw)` з кроку 04).
- **Як читач знаходить місце за 10 секунд**: відкриває файл `corpus/<docId>.md` (наприклад, `corpus/doc-05.md`), переходить за шляхом заголовків `heading` (`› 3. Спеціальні коди діагностики...`) або бере зріз `normalize(text).slice(1814, 2649)` і бачить точний абзац першоджерела.
- **Механічна перевірка (`validateAnswer`)**: функція `validateAnswer(answer, served)` витягує з тексту відповіді всі маркери `/\[([a-z0-9][a-z0-9-]*#\d{4})]/gi` і повертає помилку, якщо відповідь не містить жодної цитати або якщо хоча б один процитований `id` відсутній серед `served` (тих 5 фрагментів, які реально були передані моделі в промпті).

## 4. Правило відмови (теги `unanswerable`)
- **Порогом НЕ є бал RRF**: максимальний бал RRF залежить лише від порядкових номерів (`1/61 + 1/61 = 0.03279`) і буде високим навіть тоді, коли обидві гілки знайшли нерелевантний фрагмент за випадковим прийменником.
- **Критерій відмови**: дворівневий захист:
  1. На рівні ранжувальника: якщо максимальна косинусна подібність серед топ-5 становить `maxCosine < 0.22` (або в гілці BM25 немає жодного змістового терма з високим IDF), видача позначається як низькодостовірна.
  2. На рівні генератора відповіді: системна інструкція зобов'язує модель перевірити, чи містять видані фрагменти `<context>` пряму відповідь на запитання, і за її відсутності повернути стандартизовану відмову `«В наданих документах немає інформації...»` без жодних цитат.
- **Як відкалібровано**: на запитах `q-16` (HNSW `pgvector` у PostgreSQL), `q-17` (WebSocket GraphQL у Kubernetes) та `q-18` (штрафи комерційного SLA) максимальний косинус становить `0.0000–0.1810`, тоді як на відповідних запитах `q-01..q-15` косинус релевантного фрагмента лежить у діапазоні `0.3800–0.8200`. Усі 3 запити `unanswerable` отримують чесну відмову.

## 7. Межі
- **Відсутність морфологічного стемінгу / лематизації української мови**: слова у різних відмінках («документа», «документів», «документом») є різними токенами для BM25; частково це компенсується векторною гілкою.
- **Відсутність списку стоп-слів**: загальні сполучники та займенники («як», «що», «для») не видаляються перед BM25, але мають мінімальний IDF через присутність майже в усіх фрагментах.
- **Відсутність крос-енкодерного переранжування (Reranking)**: у v1 ми використовуємо RRF без виклику `rerank` з Vercel AI SDK 7; за даними Anthropic Contextual Retrieval, додавання reranker після гібридного пошуку BM25+Embeddings дозволяє додатково знизити частку промахів із `2,9%` до `1,9%` (на 67% від початкової бази).
