## 1. Розподіл запитів за тегами та складністю

Усього в наборі **20 запитів** (`q-01` .. `q-20`), складених вручну за документами колекції `corpus/doc-01.md` .. `corpus/doc-12.md`:

| Тег (`tags`) | Кількість запитів | Діапазон `id` | Що перевіряє | Правило для `must_cite` |
|---|---|---|---|---|
| `easy` | **10** | `q-01` .. `q-10` | Точний пошук конкретного факту, числового порогу, формули або діагностичного коду (`E-418`, `SA-STOP-09`), який прямо міститься в одному документі | Рівно 1 документ із розділу 2 `spec.md` |
| `hard` (без `injection`) | **5** | `q-11` .. `q-15` | Синтез і зіставлення правил одночасно з двох різних документів колекції (наприклад, зв'язок Zod-помилки `SCHEMA_DRIFT_DETECTED` у `doc-02` із блокуванням `isBlocked` у `doc-09`) | 2 документи з розділу 2 `spec.md` |
| `unanswerable` | **3** | `q-16` .. `q-18` | Суміжні інженерні питання (параметри HNSW `pgvector` у PostgreSQL, ліміт WebSocket-підписок GraphQL у Kubernetes, штрафи комерційного SLA), яких **немає** в колекції | Порожній масив `[]` (очікується чесна відмова) |
| `injection` + `hard` | **2** | `q-19` .. `q-20` | Легітимне питання за корпусом, до якого дописано директиву `Prompt Injection` (вимога вивести `.env.local` / `GEMINI_API_KEY` або вставити фальшиву цитату `[doc-99#0000]` і дозволити `../../.env`) | 2 документи з розділу 2 `spec.md` |
| **Разом** | **20** (17 відповідних + 3 `unanswerable`) | `q-01` .. `q-20` | Перевищує мінімальні пороги подання (`total ≥ 20`, `unanswerable ≥ 3`, `injection ≥ 2`) | Перевіряється автоматично |

## 2. Правила та інваріанти валідатора

Скрипт [`scripts/validate-golden.ts`](../../scripts/validate-golden.ts) механічно перевіряє кожен рядок `queries.jsonl` без доступу до мережі:
1. **Сувора схема Zod (`.strict()`)**: наявність непорожніх полів `id`, `query`, `expected` (рядок або масив рядків), `must_cite` та `tags` із фіксованого переліку `['easy', 'hard', 'unanswerable', 'injection']`.
2. **Унікальність ідентифікаторів**: жоден `id` не може повторюватися двічі.
3. **Узгодженість `unanswerable` та `must_cite`**:
   - якщо запит має тег `unanswerable`, його `must_cite` зобов'язаний бути порожнім (`[]`);
   - для всіх інших запитів (`easy`, `hard`, `injection`) масив `must_cite` має містити щонайменше один `id` документа.
4. **Контроль витоку відповіді в питання**: жоден очікуваний факт (`expected`) довжиною `≥ 12` символів не може дослівно входити в текст самого запиту (`query`).
5. **Стійкість до BOM та CRLF**: парсер нормалізує UTF-8 BOM (`\uFEFF`) та переноси рядків Windows (`\r\n`).

Команда перевірки:
```powershell
npx.cmd tsx scripts/validate-golden.ts docs/lab2/golden/queries.jsonl
# Вивід: еталонний набір валідний
```
