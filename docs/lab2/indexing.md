# Індексація колекції

## 1. Колекція
- **Документів**: `12` (вимога курсу: 10–40) · **символів усього**: `31 964` · **мова(и)**: українська (з технічними ідентифікаторами та назвами функцій латиницею).
- **Де лежить**: тека [`corpus/`](../../corpus/) у корені репозиторію (`corpus/doc-01.md` .. `corpus/doc-12.md`) · **як відтворюється**: файли в кодуванні UTF-8 без BOM лежать безпосередньо в git, а індекс перезбирається однією командою `npm run index` (`tsx scripts/build-index.ts`).
- **Імʼя файлу = `id` документа зі `spec.md`**: так (`corpus/doc-01.md` → `doc-01`, …, `corpus/doc-12.md` → `doc-12`), щоб ідентифікатори в індексі на 100% збігалися з полем `must_cite` в еталонному наборі `docs/lab2/golden/queries.jsonl`.

## 2. Правило фрагментації і чому саме таке
- **Межі**: спочатку за заголовками Markdown (`#`, `##`, `###`), причому текст заголовка залишається всередині розділу, а повний ієрархічний шлях заголовків (`doc-05: Гібридний пошук... › 2. Злиття рангів...`) записується в поле `heading`. Якщо розділ перевищує `maxChars`, він додатково ділиться у другій половині вікна за межами абзаців (`\n{2,}`), речень (`/[.!?…»]\s/g`) або слів.
- **Числа**: `RULE = { maxChars: 1200, minChars: 200, overlapChars: 120 }` (`src/rag/chunk.ts`).
- **Чому**: кожен із наших 12 документів складається з 3 логічних тематичних підрозділів обсягом близько `750–1050` символів кожен. На фоні орієнтирів вендорів (OpenAI — 800 токенів із перекриттям 400, базовий приклад Google — 200/20, Anthropic Contextual Retrieval — кілька сотень токенів зі збереженням контексту заголовка) вибір `maxChars = 1200` дозволяє зберегти кожен підрозділ нашого корпусу як цілісну смислову одиницю без розриву таблиць чи формул посередині, а `minChars = 200` приклеює короткий заголовок документа `H1` до першого підрозділу. Перекриття `overlapChars = 120` (10% від вікна) страхує довгі розділи (як у `doc-10`) від втрати факту на межі розрізу.
- **Що вийшло** (точний вивід `npm run index`):
  - **фрагментів**: `37` (`doc-01`..`doc-09`, `doc-11`, `doc-12` — по 3 фрагменти; `doc-10` — 4 фрагменти);
  - **довжина**: медіана `875` симв., мін `385` симв., макс `1090` симв.
- **Нормалізація тексту**: `raw.replace(/^\uFEFF/, '').replace(/\r\n/g, '\n').replace(/[ \t]+$/gm, '')` — BOM прибрано, переноси `CRLF → LF`, пробіли й табуляції в кінці рядків прибрано.

## 3. Ембедінги
- **Шлях**: Шлях А (типовий, `$0.00`, без хмарних ключів) — локальний контур `ollamaEmbedder` (`ollama:embeddinggemma-2:270m`), з повною підтримкою Шляху Б (`geminiEmbedder`, `google:gemini-embedding-2@768` через `npm run index -- --provider google`) та детермінованого офлайн-ембедера `fakeEmbedder` для CI-тестів у [`src/rag/embed.ts`](../../src/rag/embed.ts).
- **Модель із тегом або версією**: `ollama:embeddinggemma-2:270m` (або резервний `google:gemini-embedding-2@768`).
- **Розмірність**: `768` вимірів · `taskType` (для Gemini): `RETRIEVAL_DOCUMENT` під час індексації та `RETRIEVAL_QUERY` під час пошуку.
- **Чому ці документи можна було б надіслати і на безкоштовний рівень Шляху Б**: усі 12 документів у `corpus/` є авторськими навчальними конспектами під відкритою ліцензією CC BY 4.0 / MIT і не містять персональних даних, комерційної таємниці чи закритого коду замовників.

## 4. Індекс
- **Де**: [`data/index.json`](../../data/index.json) · **розмір**: `0.14 МБ` · **у git**: так (завдяки округленню векторів функцією `round6` до 6 знаків після коми файл займає лише 140 КБ і безпосередньо доступний у CI та при деплої на Vercel).
- **Чим шукається**: косинусна подібність (`cosineSimilarity` з пакета `ai`) повним перебором по масиву `index.chunks` у поєднанні з лексичним індексом BM25.
- **Чому не база**: на масштабі 12 документів і 37 фрагментів (× 768 вимірів = 28 416 чисел з рухомою комою) повний перебір у пам'яті Node.js виконується менш ніж за `0,5 мс`, тому зовнішня векторна СУБД (`pgvector`, `sqlite-vec` або `Turso`) лише додала б зайву інфраструктурну залежність без виграшу у швидкості.
- **Час побудови**: `0.07 с` у детермінованому локальному режимі (до `4.2 с` при холодному старті локального демона Ollama).

## 5. Відтворюваність
- **Команда перебудови**: `npm run index` (`tsx scripts/build-index.ts`)
- **Повторний запуск дає**: ідентичні `id` фрагментів (`doc-01#0000` .. `doc-12#0002`), ті самі символьні межі `start`/`end`, ті самі контрольні суми `sha256` та рівно `37` фрагментів.
- **Що саме НЕ побайтово однакове і чому**: поле `builtAt` (часова мітка ISO-8601 моменту запуску) та при використанні різних апаратних збірок GPU/CPU в Ollama — 6-й знак після коми у векторах через неасоціативність операцій IEEE 754 float32.
- **Перевірки в CI**: [`tests/chunk.test.ts`](../../tests/chunk.test.ts) та [`tests/index.test.ts`](../../tests/index.test.ts) — виконуються офлайн без мережі та перевіряють, що жоден документ у `corpus/` не змінився після побудови `data/index.json`.

## 6. Що зберігається для цитування (вхід кроку 05)
Кожен запис у `data/index.json` зберігає стабільний `id` фрагмента (`doc-XX#YYYY`) → `docId` + точні 0-based символьні зсуви `start` і `end` у нормалізованому тексті + ієрархічний шлях заголовків `heading`. Інваріант `normalize(readFileSync(d.path, 'utf8')).slice(c.start, c.end) === c.text` перевіряється автоматично в `tests/index.test.ts`.
