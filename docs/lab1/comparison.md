## Власний цикл vs AI SDK (заповните на кроці 09)

| Що | Власний цикл (крок 08) | AI SDK 7 |
|---|---|---|
| Рядків коду разом з інструментами | 185 рядків (`agent-loop.ts` + `tools.ts`) | 82 рядки (`agent-aisdk.ts`) |
| Історія повідомлень, розбір викликів інструментів, повтор | Власний масив `Message[]` та цикл `runAgentLoop` (40 рядків) | `ToolLoopAgent` і `agent.generate()` (автоматично) |
| Ліміт кроків | Власний лічильник `for (step = 1; step <= maxSteps; step++)` | `stopWhen: isStepCount(n)` |
| Бюджет токенів | Перевірка `usage.inputTokens + usage.outputTokens >= tokenBudget` | Доступний через `steps[i].usage`, обмежується через кастомні hooks |
| Облік токенів | Нормалізація `fromMessagesUsage`/`fromChatUsage` та `addUsage` | `result.usage` (сума), `result.steps[i].usage` (за кроками) |
| Валідація структурованого виходу | `output.safeParse(extractJson(turn.text))` з повторним запитом | `Output.object({ schema: Report })` |
| Підтвердження деструктивної дії | Відсутнє (лише інструменти читання L1) | `toolApproval: { write_file: 'user-approval' }` та двоетапний `generate` |
| Друга форма API або провайдер | Окремі модулі адаптерів `messagesModel` / `chatCompletionsModel` | Зміна провайдера `google()` / `createOllama()` у `pickModel()` |
| Що зникло / що з'явилося | Зник ручний парсинг викликів інструментів, з'явилося безпечне підтвердження деструктивних дій кодом SDK. |

- Що ваш цикл зробив гірше за агента кодування (і чого він не вміє: запис файлів, запуск тестів): Власний цикл працює на рівні L1 (лише читання), тому він не може самостійно застосувати зміни у файлову систему або запустити `npm test` для автоматичної верифікації — це робить розробник вручну.
- Звідки різниця у вхідних токенах: Агент кодування має великий системний промпт (AGENTS.md, системні інструкції IDE), тоді як наш цикл надсилає лише короткий сфокусований `SYSTEM` промпт та історію виконаних кроків.
