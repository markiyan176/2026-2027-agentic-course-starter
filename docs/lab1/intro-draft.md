# Розділ 1: Вступ та концепція курсового проєкту

**Тема проєкту**: Агентна система автоматизованого рефакторингу, діагностики та верифікації кодових баз (Agentic Code Engineering & Verification System).

---

## 1.1. Опис проблеми та актуальність

Сучасна програмна інженерія стикається зі зростаючою складністю кодових баз, монорепозиторіїв та архітектурних вимог. Розробники витрачають значну частину робочого часу на рутинні операції:
- локалізацію та виправлення регресійних помилок;
- оновлення залежностей та міграцію застарілих API;
- написання модульних та наскрізних (E2E) тестів;
- рутинну перевірку контрактів маршрутів, лінтинг та верифікацію типів.

Традиційні підходи статичного аналізу (ліндери, компілятори) виявляють лише синтаксичні та поверхневі проблеми, не маючи семантичного контексту для їх самостійного усунення. З іншого боку, звичайні single-turn LLM-чати без агентного циклу страждають на галюцинації, не бачать результатів власних змін у середовищі виконання і неспроможні гарантувати працездатність згенерованого коду.

---

## 1.2. Обґрунтування агентного підходу (Agentic Architecture)

Для надійного вирішення інженерних задач необхідний замкнений агентний цикл (Perceive-Plan-Act-Verify Loop):
1. **Ітеративне сприйняття кодової бази**: Агент використовує стандартизовані інструменти (`list_files`, `read_file`, `search_grep`) для автономного дослідження структури проєкту без перевантаження контекстного вікна зайвими даними.
2. **Формування плану (Plan Mode)**: Перед виконанням деструктивних дій формується чіткий план, що унеможливлює "сліпі" правки та зберігає стабільність робочого дерева.
3. **Виконання дій з використанням інструментів (Tool Use)**: Зміна коду (`write_file`, `edit_file`) здійснюється точково з дотриманням архітектурних угод репозиторію (`AGENTS.md`).
4. **Автоматична верифікація зворотного зв'язку (Execution & Test Feedback)**: Агент самостійно запускає тестовий набір (`npm test`), лінтер (`npm run lint`) та збірку (`npm run build`). У разі виникнення помилки, стектрейс аналізується як нове спостереження на наступному кроці циклу (ReAct).
5. **Людина в контурі (Human-in-the-Loop)**: Критичні дії (запис у файли, виконання небезпечних команд) вимагають обов'язкового підтвердження користувачем (`toolApproval`).

---

## 1.3. Політика роботи з даними та безпека (Data Policy & Security)

Проєкт будується за принципом нульової довіри (Zero Trust) до зовнішніх агентних запитів:
1. **Сувора заборона витоку секретів**:
   - Жоден агент не має права на читання чи зміну файлів `.env`, `.env.local`, `.env.production` та приватних ключів.
   - Реалізовано багаторівневий захист: пре-хуки середовища розробки (`scripts/guard-env.mjs`), маски заборон у конфігурації інструментів (`opencode.json`), та захист на рівні ядра власного циклу (`src/agent/tools.ts`).
   - Спроби доступу реєструються в журналі дій зі статусом `denied` і поверненням коду помилки без витоку даних.
2. **Маскування чутливих даних у логах**:
   - Усі дії фіксуються в уніфікованому 6-полярному форматі `.agent-log/` (`timestamp`, `tool`, `input`, `result`, `agent`, `model`).
   - Будь-які паролі, токени доступу чи API-ключі автоматично маскуються перед записом на диск.
3. **Повна ізоляція чутливого коду (Local Offline Path)**:
   - Для конфіденційних проєктів передбачено повністю офлайн-режим на базі локального Ollama (`qwen3:4b`), де жоден байт коду не залишає межі локальної машини розробника.

---

## 1.4. Бюджетні обмеження та нульова вартість експлуатації ($0 Operational Budget)

Проєкт розроблено з урахуванням суворого $0 операційного бюджету:
1. **Багаторівнева стратегія вибору моделей**:
   - **Локальний рівень ($0.00)**: Використання Ollama (`qwen3:4b` для коду, `nomic-embed-text` для семантичного пошуку) забезпечує необмежену кількість запусків без фінансових витрат.
   - **Безкоштовний хмарний рівень ($0.00)**: Інтеграція Google Gemini API (`gemini-3.8-flash`) у межах безкоштовних квот Google AI Studio для швидкої розробки та телеметрії.
   - **Frontier за потреби**: Каталог `src/models.ts` підтримує гнучке підключення Anthropic Claude Haiku/Sonnet у разі потреби високої складності, з автоматичним моніторингом цін.
2. **Мінімізація витрат контексту**:
   - Лаконічний `AGENTS.md` (до 35 рядків) мінімізує базовий накладний оверхед системного промпту.
   - Підтримка кешування префіксів (Prompt Caching) зменшує вартість повторних викликів на 75–90%.
3. **Контроль та ліміти у власному агентному циклі**:
   - Жорсткі обмеження кількості кроків (`maxSteps: 10`) та токенного бюджету (`tokenBudget: 50_000`) у `src/agent/agent-loop.ts`.
   - Точний розрахунок вартості кожного виклику через модуль `src/cost.ts` з урахуванням українського мовного коефіцієнта та валідацією похибки (<= 10%).
