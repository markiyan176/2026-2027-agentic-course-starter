# doc-02: Протокол валідації схем Zod v4 та контракти API у проєктах курсу

## 1. Правила опису схем та примусова типізація

У всіх серверних маршрутах та CLI-скриптах репозиторію `agentic-course-starter` діє правило суворої валідації на межі системи (`Boundary Validation First`). Будь-які зовнішні дані — тіло HTTP-запиту, рядки JSONL-файлів, змінні середовища або JSON-відповіді мовної моделі — вважаються недовіреними (`unknown`) до проходження через парсер `zod` версії `4.x`. Використання конструкції `as any` або небезпечного приведення типів без попереднього виклику `.parse()` чи `.safeParse()` класифікується як дефект безпеки рівня `SEV-2`.

Для всіх об'єктних схем зовнішніх API використовується режим відсікання невідомих полів або явної відмови. У критичних контрактах верифікатора та MCP-інструментів довжина рядкових полів обов'язково обмежується методом `.max()`: для пошукових запитів ліміт становить `200 символів`, для ідентифікаторів фрагментів корпусу — `48 символів`, а для текстових обґрунтувань вердикту (`reason`) — рівно `280 символів`.

## 2. Стандарт форматування помилок валідації

Коли вхідний пакет не проходить перевірку `safeParse()`, серверний обробник не повертає клієнту сирий стек помилок Node.js. Натомість формується стандартизований JSON-конверт помилки зі статусом HTTP `422 Unprocessable Entity` та кодом `ZOD-ERR-422`. Поле `issues` у цьому конверті містить масив об'єктів, де кожен елемент включає шлях до поля через крапку (`path`), код порушення (`code`) та лаконічне повідомлення українською або англійською мовою без розкриття внутрішньої структури таблиць чи файлової системи.

Якщо невалідовані дані надходять не від користувача, а у відповіді самої мовної моделі під час структурованого виводу (`generateObject`), система фіксує подію `SCHEMA_DRIFT_DETECTED` і присвоює всьому запиту статус `unknown`, що автоматично активує блокувальну браму верифікатора згідно з правилом fail-closed.

## 3. Валідація змінних середовища при старті

Модуль конфігурації `src/env.ts` перевіряє наявність і формат змінних середовища ще до ініціалізації першого HTTP-з'єднання. Обов'язковими є параметри провайдера моделі (`PROVIDER`), ідентифікатора моделі (`MODEL_ID`) та базового URL локального сервера Ollama (`OLLAMA_BASE_URL`, за замовчуванням `http://127.0.0.1:11434/api`). Для перевірки ізоляції серверних ключів використовується скрипт `scripts/guard-env.mjs`, який сканує клієнтські компоненти з директивою `"use client"` і завершує збірку з кодом виходу `1`, якщо знаходить пряме звернення до `process.env` без префікса `NEXT_PUBLIC_`.
